HSCT-VIEW 24

Tech log 0 min

    Pick a step. Each one takes sim-time and adds to your log. New steps can appear as you learn more.

      Troubleshooting method (CompTIA)

      1. Identify the problem — question the user, note recent changes.
      2. Establish a theory of probable cause.
      3. Test the theory. If it fails, form a new theory.
      4. Plan the fix.
      5. Implement it and verify the system works.
      6. Document what happened.

      Power chain

      Wall outlet → power strip → PSU rocker switch → +5V standby (motherboard standby LED lights) → power button sends a signal via the 2-pin PWR_SW header → PSU turns on → POST. A "paperclip test" jumps the green PS_ON wire to a black ground wire to force the PSU on without a motherboard. Rails should be within 5%: +12V, +5V, +3.3V.

      Beep codes (AMI-style, typical — check the board's manual)

      1 shortPOST successful on most modern boards
      2 shortMemory parity error
      3 shortBase memory (first 64 KB) failure — RAM
      4 shortSystem timer failure
      5 shortProcessor failure
      6 shortKeyboard controller / Gate A20
      8 shortDisplay memory read/write failure — video
      1 long, 2–3 shortVideo card or video memory failure
      ContinuousPower or memory problem

      Motherboard debug LEDs

      Boards light one of CPU / DRAM / VGA / BOOT to show which stage of POST it's stuck on. DRAM lit = memory didn't train. BOOT lit = hardware fine, no bootable device found.

      BIOS / UEFI boot

      Windows installed in UEFI mode lives on a GPT disk with an EFI System partition and shows up as "Windows Boot Manager." Legacy / CSM mode only boots MBR disks and cannot see a UEFI install. Settings live in CMOS memory kept alive by a CR2032 coin cell (~3.0 V new). When it dies (~2.7 V or below) the board loses settings: wrong date, "CMOS checksum error — press F1", defaults restored.

      Common screen messages

      No SignalThe monitor is fine; nothing is sending video. PC off, not POSTing, or wrong input.
      Reboot and Select proper Boot deviceFirmware finished POST but found no bootable OS on any device it tried.
      Operating System not foundSame idea — drive missing, unbootable, or wrong boot mode.
      CMOS checksum errorBIOS settings were lost or corrupted; usually a dead battery.

      Hard drive health (SMART)

      Reallocated Sector CountBad sectors the drive moved to spares. Any nonzero number is a warning; a climbing number means the drive is failing.
      Current Pending SectorSectors that couldn't be read and are waiting to be reallocated.
      Uncorrectable Sector CountData the drive could not recover. Data loss has already happened.
      Spin Retry CountMotor had trouble spinning up. Mechanical trouble.
      Clicking soundRead/write heads failing to find tracks and resetting. The drive is on borrowed time.

      chkdsk, defrag and reinstalls are software tools. They cannot repair failing hardware, and heavy disk activity on a dying drive makes it worse. Rule: secure the user's data before anything else.
