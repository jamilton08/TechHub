Four machines. None of them get to Windows.

Shift 1 was hardware. Shift 2 was software that lied. Shift 3 is the layer in between: the firmware. Every ticket stops before the operating system even loads, and the only tools that reach that far are the Setup utility, a screwdriver, and the sticker on the case.

Each ticket is a real machine with a live monitor. Power it on, read what the screen says, press the setup key, and work inside four different firmware utilities. Some problems are a setting. Some are a part. A few are both, and the machine will tell you which — if you read every word.

      Physical work: parts, jumpers, cables, the wall plug. Some of it is the fix. Some of it is expensive. The screen tells you which.

        How to read a machine that won't boot

        1. Read the screen word for word. Firmware messages are short and exact; every one of them names the layer that failed.
        2. Find the target: the asset sticker or the image spec says what the settings are supposed to be. Compare, don't guess.
        3. Change what's wrong, save once (F10), watch the next boot. A different message is progress. The same message means you changed the wrong thing.
        4. When it boots, ask whether the cause is fixed or just the symptom. Cold-boot test if the answer depends on it.
        5. Write down what you changed. The next tech has to be able to undo it.

        Getting into Setup

        At POSTDel or F2 in the first seconds (varies by maker; the screen says which). F12 is usually a one-time boot menu.
        From WindowsSettings → System → Recovery → Advanced startup → Troubleshoot → UEFI Firmware Settings. Works when Fast Boot skips the key window.
        Inside↑↓ move · ←→ change tab · + − change a value · Enter open · Esc back · F9 load defaults · F10 save & exit. Nothing is saved until you save.

        POST messages and what they mean

        Reboot and Select proper Boot device / No bootable devicePOST finished, the firmware walked the whole boot list, and nothing in it was bootable the way it's configured. Detected is not bootable. Check boot mode, boot order, and whether the drive is excluded or disabled.
        CMOS checksum error — Defaults loadedThe settings memory was lost, so the board loaded factory defaults. Every setting the image depends on may now be wrong. Usually a dead coin cell.
        Time-of-day clock stopped / date is years wrongNothing kept the clock running while the power was off. Coin cell.
        Overclocking failed! Enter setupThe board tried a saved memory or CPU profile and training failed. It will try the same profile every boot until you change it.
        CPU fan errorNo RPM on the CPU_FAN header. Wrong header or a dead fan. Don't disable the warning.
        PXE-E61 / PXE-M0FThe network card tried to boot from a server and gave up. Harmless by itself; a sign that network boot is ahead of the disk in the order.
        System DisabledToo many wrong firmware passwords. Power-cycle to try again.
        Beeps1 short = POST OK. Repeating short or 3 long = memory. 1 long + 2 short = video. 5 short = CPU. Continuous = power or short circuit.

        Boot mode: UEFI vs Legacy (CSM)

        UEFI boots from a GPT disk through a small file (Windows Boot Manager). Legacy/CSM boots from an MBR disk through boot code in its first sector. A disk written one way cannot boot the other way — so a Windows 11 drive (GPT) in Legacy mode is "detected" and still unbootable. Windows 11 requires UEFI. Turning CSM on also turns Secure Boot off, and Secure Boot can't be turned back on until CSM is off. Boot order is the list the firmware walks, top to bottom; a one-time boot menu (F12) picks a device without changing the list.

        Secure Boot, TPM, BitLocker

        Secure BootThe firmware only runs signed boot loaders. Required by Windows 11 and by most testing and anti-cheat software.
        TPM / fTPMA security chip — usually built into the CPU (fTPM, PTT) and just switched on or off in Setup. Stores keys. Windows 11 requires TPM 2.0.
        BitLockerDrive encryption. The TPM releases the key automatically only if the boot measurements match what it sealed the key with: firmware, Secure Boot state, boot mode, boot loader. Change any of them and BitLocker asks for the 48-digit recovery key. Typing the key gets you in today; it does not change why it asked.

        Drive settings

        SATA Operation / SATA Mode: AHCI is what modern Windows expects. Switching to IDE/ATA or RAID after Windows is installed presents the drive with a different driver than the one Windows loaded at install → INACCESSIBLE_BOOT_DEVICE (0x7B). The drive is fine; the setting changed. Ports can also be individually disabled.

        The CMOS battery

        A CR2032 coin cell, 3.0 V new. It keeps the clock and settings alive when the machine has no power at all — unplugged, or a power strip switched off. With the plug in, standby power does that job, which is why a dead cell shows up "every morning" in an office and never in a lab. Symptoms: date reset, checksum error, defaults loaded, drive settings reverting. Lifespan 5–10 years; below ~2.6 V it's done. Replacing it does not restore your settings.

        Clear CMOS (a jumper or pulling the cell) = load defaults and forget everything: date, boot order, fan curves, XMP, the lot. It's the right tool when you're locked out of a desktop. It's a sledgehammer when you can see the three settings that are wrong. Laptops keep their firmware passwords in the embedded controller, not CMOS: pulling the cell won't clear one.

        Memory profiles

        RAM runs at a safe default (JEDEC, 2133–2666) until you enable the profile printed on its sticker: XMP (Intel), DOCP/EXPO (AMD). The sticker's speed is the rated one. A higher profile than the sticker, or a mismatched pair, fails memory training: random restarts, "Overclocking failed," a DRAM debug LED.

        Firmware passwords

        Supervisor / AdminSet by IT. Full access to Setup. On managed devices it's recorded in the asset system, not on the machine.
        User / Power-onAsked at every boot. Gets past the prompt; inside Setup it can usually only change itself. Boot order and Secure Boot stay locked.
        PolicyNo bypass tools or "master password" sites on school devices. Get the recorded password. Three wrong tries disables the machine until a power-cycle.

        Cost of being wrong

        Swapping a part that works costs money, an hour, and sometimes someone's files. Wiping settings you didn't need to wipe costs the next tech a day. A fix that "works for now" costs a second ticket next week. Reading costs nothing.
